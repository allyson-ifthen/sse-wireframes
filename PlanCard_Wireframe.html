Plan Card — unified component spec

Single source of truth for the plan card used on Residential Plans, Commercial Plans, Promo Pages, and the new IES Fixed Bill page. Replaces three legacy class systems (.plan-card, .offer-card, .comm-plan-card) with one component that exposes variants and states.

PC-D16 newNew "in-flow switch" variant — for an already-enrolled customer choosing a different plan mid-flow (Enrollment Select Plan step, both Enrollment files), not a new-customer marketing context. Three changes from the standard card: (1) CTA override, exception to PC-D2 — reads "Select this plan →" instead of "Start Enrollment →"; the card matching the customer's already-selected choice omits the CTA slot entirely (selection is confirmed via a page-level Continue button, not a per-card action). (2) "Selected" is a card-level outline state, not a badge — .pc.inflow.selected gives the card a 2px blue border, same visual mechanism as .featured/.promo's border treatment, not a new badge-row entry; "Most Popular" (badge-popular) is unaffected and can still appear on any card in this grid. (3) No ETC/ETF callout on the card — a switching fee is triggered by leaving the customer's current plan, not by the alternative being displayed, so it doesn't belong on every card in the grid; that information belongs on the sticky current-plan summary (outside this component) instead, attached to the plan it actually describes. (4) Color token override — this variant's CTA and selected-state border use the in-app blue accent (#2b5d8a), not PlanCard's standard marketing orange, since it's an authenticated in-app context, not a public marketing surface. Scoped 2026-09-03 (Allyson) from patterns already ad-hoc-built (and byte-identical) in both Enrollment_IL-IES_Wireframe.html and Enrollment_ONG-PA-GRE_Wireframe.html's Select Plan switch-to grids — those files' own dev notes always intended this component to replace their local markup. Not yet done, flagged separately: porting the finished enrollment files over to actually use this component, and relocating OPG's existing per-card ETC callout (.pp-etf-callout) to its own sticky current-plan summary to match point (3) above — see Wireframe_ChangeLog_Active.md ENRIL-305 for tracking.§15 In-flow switch (new)

13 Copy length guidance for marketing teams Hand to anyone authoring per-plan content · enforces mobile-desktop parity

Mobile and desktop render the same copy (walkthrough rev 2026-05-14). To keep cards from breaking layout at ~320px mobile width, marketing copy for each slot must respect a hard ceiling. These ceilings are calibrated against the wireframe — if any per-plan copy exceeds the ceiling, shorten the source content rather than introducing a mobile-only variant.
